# 豆播 AI

微信原生 TypeScript + TDesign 小程序、React 管理后台、Go API 与 Worker。
关系数据使用 MySQL，共享会话和限流使用 Redis，正式环境文件使用阿里云 OSS。

## 本地启动

需要 Go 1.26、Node.js 22.12+、MySQL 8.4；混剪另需含 libass 的 FFmpeg、FFprobe 和中文字体。当前电脑已准备独立 MySQL 与 FFmpeg 9.0.2，其他电脑可配置已有服务，或使用下方 Docker 环境。

```powershell
cd F:\cluade\doubo\douboadmin
cd web
npm ci
cd ..\miniprogram
npm ci
npm run build
cd ..
.\deploy\start-local.ps1
```

脚本会构建 API、启动已安装的本地 MySQL、执行显式数据库迁移，再启动 API 和 Vite。已有服务占用 8080 / 5173 时会提示，不会终止其他程序。
日志和 PID 在 `.runtime/local-*`，MySQL 日志在 `.runtime/mysql-error.log`。

管理员使用 `ADMIN_USER` / `ADMIN_PASSWORD`。未覆盖时本地账号为 `admin` / `doubo-demo-2026`；正式环境要求更换为至少 16 位的密码。

微信开发者工具导入 `miniprogram/`，使用真实 AppID，然后选择“工具 → 构建 npm”并重新编译。
本地调试需在开发者工具允许不校验合法域名；手机必须能访问电脑局域网 API 地址。正式发布使用已配置的 HTTPS 域名。
微信登录配置及真机说明见 [docs/wechat-login.md](docs/wechat-login.md)。

## 使用模型与模板

1. 在服务端设置 `RELAY_BASE_URL=https://relay.tcmzhan.com` 和 `RELAY_API_KEY`，重启 API / Worker。`/keys` 是密钥管理网页，不是 API 前缀。
2. 后台“模型管理 → 同步上游”。同步保留本地名称、积分配置、排序、上下架与删除标记；消失的上游模型标为不可用。
3. 点击“配置”进入流光同款的宽表单：编辑基础信息、图标标签、能力选项、参考素材限制、提示词、分档积分和错误映射；支持设置维护状态。能力选择会影响小程序可选参数，并由任务接口再次校验。
4. 图片、视频、文本模型可以上架到小程序；已支持的 `tts-*` 音频模型用于混剪配音。3D、超分保留在目录中。
5. “创作模板”中创建风格主题或灵感做同款模板，上传封面、填写提示词、选择真实模型及参数，再上架。
6. 激活后的用户从 `/api/config` 和 `/api/templates` 获取配置，提交任务后由后端异步执行，在任务详情或我的作品查看结果。未激活用户看不到业务目录，也不能调用创作接口。

后台“系统设置”可配置积分兑换率、充值金额范围、混剪积分、默认改写/配音模型、审核开关、推荐词与告警阈值。模型的分档积分用于服务端报价；开启扣费后，任务提交预留积分，成功扣除，明确失败退回。未知上游结果保留待核实，管理员核实后可释放。钱包、流水与任务状态在同一 MySQL 事务内变更。

充值按输入金额购买积分，没有套餐。微信支付采用官方 APIv3 JSAPI 接入，只有验签通知或服务端查单确认成功才到账，支持关闭订单、全额退款与自动查单。配置项与启用步骤见 [接入配置](docs/business-integrations.md)；商户产品资格与真机支付还未验收，iOS 充值默认关闭。

## 混剪与运营

- 混剪页支持最多 10 个素材、镜头检测、画面比例/分辨率/时长、ASR、AI 改写、多音色配音、字幕、背景音乐和原声。未配置 ASR/抖音时，可直接上传自有素材完成混剪。
- 抖音适配 TikHub：搜索、详情、热词、缓存、历史及素材导入；综合/点赞/最新排序使用上游能力，播放量仅对当前页已有数据排序。
- 我的页面新增积分、充值订单、站内通知和设置；作品可在审核通过后生成 30 天有效的分享短链，也可删除。删除或驳回后分享失效。
- 后台提供用户启停、积分调整与流水、订单、独立支付记录及退款记录、作品管理、人工内容审核、背景音乐管理、每日统计、模型估算成本、节点心跳/队列/错误日志/告警。行为分析默认关闭，由用户主动选择开启。
- 字幕优先使用 ASR 时间轴；缺少时间轴或文案经过改写时会明确标为估算时序。配音实调有一笔提交结果未确认，已停止自动重发；目前不能宣称真实配音全链路已验收。

## 切换测试数据库和 OSS

收到测试环境后，在 `.env.local` 修改：

```dotenv
STORAGE_DRIVER=mysql
MYSQL_DSN=doubo:password@tcp(test-db:3306)/doubo?charset=utf8mb4&parseTime=true
RELAY_BASE_URL=https://relay.tcmzhan.com
RELAY_API_KEY=在本地填写
OSS_REGION=cn-hangzhou
OSS_BUCKET=在本地填写
OSS_ACCESS_KEY_ID=在本地填写
OSS_ACCESS_KEY_SECRET=在本地填写
```

先执行迁移，再重启服务并同步模型。临时预览模板不会自动写入新数据库；需要迁移的正式模板及本地文件应单独确认和转存。
正式环境再设置共享 `REDIS_ADDR` / `REDIS_PASSWORD`，并通过 HTTPS 访问服务。

## 单机 Docker 部署与扩容

复制 `.env.example` 到 `.env`，填写 MySQL、Redis、微信、中转、OSS 等配置。生产部署设置 `APP_ENV=production`、`ALLOW_DEMO_LOGIN=false` 和非默认管理员密码。

```sh
docker compose --env-file .env -f deploy/compose.yaml up -d mysql redis
docker compose --env-file .env -f deploy/compose.yaml run --rm migrate
docker compose --env-file .env -f deploy/compose.yaml up -d --build api worker web
```

管理入口监听 `127.0.0.1:8088`，由服务器 HTTPS 反向代理对外提供服务。
增加实例可使用 `docker compose ... up -d --scale api=2 --scale worker=2`；跨服务器需所有实例连接同一组 MySQL、Redis 和 OSS，通过负载均衡访问 API。
生产启动会检查共享依赖，禁止用内存存储扩容。

任务幂等键防止重复入队；MySQL 行锁、租约令牌防止重复领取和过期回写；执行记录持久保存上游任务编号，恢复后继续查询。
上游未明确提供提交幂等保证，断网导致“提交成功与否未知”时会停止自动重发，避免重复消耗额度，需管理员在中转站核实。
更多恢复流程见 [docs/relay.md](docs/relay.md)。

## 验证

```sh
node scripts/check-structure.mjs
cd server && go test -race ./... && go vet ./...
cd ../web && npm run build && npm run test:e2e
cd ../miniprogram && npm run build
node --test scripts/*.test.cjs
```

小程序 `flow.test.cjs` 是对运行中 API 的只读集成测试，通过 `DOUBO_TEST_API` 指定地址，不消耗生成额度。
MySQL 并发测试需设置 `MYSQL_TEST_DSN`，数据库名必须包含 `_test`，不能指向业务库。
浏览器测试会创建标注为测试的临时模板并在结束后删除；不调用生成模型。
单元测试中的 HTTP fixture 仅用于验证错误、重试和并发，不参与应用运行。

已实测文本回复、图片生成和纯素材 FFmpeg 混剪；自动化测试覆盖签名/解密、重复到账、并发积分、退款、审核分享、混剪渲染及界面边界。MySQL 测试使用两个独立连接实例；通知与上游协议测试使用隔离 HTTP fixtures，不替代真实商户、抖音、ASR、OSS 和微信真机验收。

Web 首屏 JS gzip 约 71.8 KiB，全部 JS 分块约 117.9 KiB，CSS 为 8172 字节 gzip（低于 8 KiB）；服务商业务作为独立懒加载模块，约 8.7 KiB gzip。首屏 80 KiB、CSS 8 KiB、原六个独立管理页面各 2 KiB 的预算不变。原共享预算 100 KiB 拆为其他代码 98.5 KiB 与用户页原有份额 1.5 KiB，用户页因新增授权功能增加 1.5 KiB（合计上限 3 KiB）；新增服务商模块单独限制 12 KiB，没有把依赖移到外部 CDN 或增加前端运行时库。共用表格、分页和页面容器合并到共享分块，减少重复加载开销。

运行监控默认展示在线节点，可切换查看全部实例记录；错误日志和告警在同一区域切换，刷新会同步更新节点、日志与告警。每 15 秒自动更新，超过 60 秒未上报心跳标记离线。服务接入中的“已配置”表示存在配置，不代表已完成云端连通性验证；MySQL 状态使用后端实时探测结果。

后台主栏目通过 URL 锚点定位，支持刷新与前进后退；编辑弹窗打开时，浏览器返回优先调用弹窗的关闭/草稿确认流程。窄屏菜单支持关闭按钮、遮罩和 Esc，浏览器返回先关闭菜单并解除页面锁定，再次返回才切换栏目。列表区分加载失败和空数据，刷新已有数据不插入额外占位；筛选用户、订单、作品或审核状态后重置列表页码，翻页后回到表格顶部，单页列表隐藏翻页按钮。

系统设置的未保存修改在切页、刷新、重试、退出及浏览器刷新前受保护；保存中锁定表单，推荐搜索词保留输入中的换行，仅提交时去空行与首尾空格。请求结果绑定查询地址，修改服务端筛选/分页后不沿用旧查询的数据，同一查询刷新失败则保留已加载内容。弹窗与移动菜单复用焦点循环、顶层关闭和计数式滚动锁。

后台视觉按 ui-styles 的“实用优先”原则统一：浅色侧栏按内容、交易、平台分组，颜色变量集中在 `web/src/styles/base.css`，主按钮与选中状态使用同一绿色体系。概览首屏展示指标、趋势和成本，日明细与行为事件按需展开；图表使用真实数据，零值不绘制柱形，90 天范围在手机宽度内完整展示。模型配置保留原有字段与分区结构，模板列表保留真实封面，不添加虚构内容填充页面。

模板、音乐表单使用固定标题和操作栏，中间字段独立滚动；模型、用户、订单、作品、审核和音乐列表的操作列固定在右侧。搜索框支持原生清除入口并高亮焦点。用户详情突出可用与预留积分，读取失败显示未知并提供重试；账号启停放入独立折叠区，避免与积分调整混淆。

小程序引用源码估算约 451 KiB，包含 TDesign 按需依赖，低于现有 512 KiB 预算；这不是微信最终上传包大小。二维码由 Go 服务端生成，小程序无需额外二维码依赖。

构建检查手写文件不超过 300 行。当前一般管理列表显示近期记录（任务最多 200、通用记录最多 500）；独立支付记录支持完整后端分页。财务补单通过独立游标轮询未结算记录，业务看板按所选日期统计，不受列表截断影响。
