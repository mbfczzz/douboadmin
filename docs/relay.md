# 中转站接入与任务恢复

配置仅在 Go 服务端：`RELAY_BASE_URL`、`RELAY_API_KEY`。密钥不会通过 `/config`、模型目录或日志返回给前端。
`https://relay.tcmzhan.com/keys` 用于管理密钥；请求基址为 `https://relay.tcmzhan.com`。

## 协议

- `GET /v1/models`：读取模型、能力、参数、上游基础消耗及计费规则。
- `POST /v1/images/generations`：文字生成图片。
- `POST /v1/images/edits`：参考图编辑，提交 `image_urls`。
- `POST /openapi/v1/generations`：视频，使用 `t2v/i2v/keyframe/omni_ref`；按能力提交图片、视频、音频 URL。
- `POST /v1/chat/completions`：Agent 文本回复；历史由后端按当前用户读取最近成功对话。
- `POST /v1/audio/speech`：已支持的 `tts-*` 配音模型，传 model/input/voice，支持异步任务与 audio.url。
- `GET /v1/tasks/{id}`：查询异步任务。

模型 ID 使用上游 key 的确定性散列作为数据库唯一键，多个 API 实例同时同步不会插入重复模型。
同步只更新上游负责的参数与能力，保留管理员名称、积分配置、顺序、上架和删除决定。冲突会计数返回，不覆盖其他管理员的修改。
模型配置沿用流光的宽弹窗分组表单，包含基础信息、能力选项、参考素材限制、提示词、积分矩阵、错误映射和状态。`settings` 独立保存运营配置，同步不会覆盖；实际可用规格取运营选择与上游能力的交集。成本价及错误匹配规则不会返回给小程序。
新增模型必须出现在当前密钥可用的上游目录中，不能配置一个不存在的模型伪装成可用。

## 执行状态

业务 `jobs` 与上游 `executions` 分开保存。首次执行先原子创建 `submitting` 记录，只有获胜者可以调用上游生成接口。
收到异步编号后持久化为 `polling`，后续实例只做查询。同步结果也会先保存到执行记录，再写入文件存储。
任务租约在有界网络请求前延长，释放后按时间继续轮询；完成回写必须匹配当前有效租约令牌。

生成结果先转存到自有 OSS；未配置 OSS 的本地开发环境转存到 `media/results/`。
使用确定性结果对象键处理上传成功但数据库写入中断的情况，恢复时不会再次调用生成模型。
下载仅允许公网 HTTPS 目标，限制文件体积、类型、重定向及连接超时。

## 失败与恢复

- 明确的上游拒绝或生成失败：用户可以用新幂等键重试。
- 已有上游编号但临时查询失败：继续查询，不重新生成。
- 超过一小时或结果保存异常：任务提示管理员处理；后台详情的“恢复查询 / 保存”会继续已有任务，不发起新生成。
- 网络中断、进程中止等导致提交结果不确定且没有任务编号：停止自动重发。后台显示“提交结果待核实”，需要先在中转站核对订单、任务与消耗记录。

这不是跨第三方系统的“绝对 exactly once”承诺：上游没有可验证的提交幂等协议时，不能同时保证未知结果下自动恢复和绝不重复扣费。因此未知状态采用人工核实。

## 本地预览与后续测试环境

用户已允许在测试数据库 / OSS 提供前使用临时预览数据。`preview-product`、`preview-travel`、`preview-food`、`preview-portrait` 是明确标注的本地样例，所有读取和编辑仍经过后端。
这些模板不是自动启动种子，也不会自动复制到新测试数据库。模型来自实时中转目录，生成请求仍是真实调用。
当前代码有 MySQL 并发、模拟 HTTP 上游协议、幂等和恢复测试，并完成过一次真实文本调用、一次真实图片生成。视频、OSS 和微信真机的最终验收需在测试环境补做。

积分配置已接入报价、预留、扣减与返还；支付、充值订单与退款账本见 [接入配置](business-integrations.md)。当前本地扣费与充值均关闭，开启后由服务端计价，禁止客户端指定应扣金额。

本地混剪引擎已移除；真实配音实调有一笔提交状态未知，已停止自动重发。执行状态与中转消耗需要先核实，不能把 HTTP fixtures 的通过当作真实配音验收。
