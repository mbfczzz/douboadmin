# 邀请码分享卡片

沿用豆播深色/青色主题，以真实服务商名称、邀请码用途、原始小程序码、可复制邀请码和微信扫码说明组成 720×1060 PNG 卡片。白色码区保留完整码图与留白，不覆盖中心图案、不裁切、不开启滤镜。卡片中的“微信扫码进入”是扫码说明，不声称图片可以点击跳转。

后台预览与下载使用同一张 PNG；小程序页面显示相同设计元素，保存时复用 `miniprogram/utils/invite-poster.ts` 的绘制函数，避免两套导出版式漂移。原码图仍在私有 OSS，分享卡片本地合成导出，不额外上传每次生成的海报，也不改变邀请码/角色/审批。画布与图片生命周期失败时给出重试，保存相册后清理临时文件。

后台通过原有带权限的码接口 `?image=1&code=<当前邀请码>` 读取原图用于 Canvas，避免要求私有 OSS 开放浏览器跨域读取权限。接口不接收任意远程URL；权限与原码接口一致；码被重置后返回409，避免新码图配旧文字。普通看图仍走 OSS HTTPS。

## 范围与验证

浏览器以隔离测试服务商验证大屏/窄屏预览和 PNG 下载；示例预览不代表真实业务邀请码或已完成微信真机扫码验收。实际投放使用微信接口生成的原始小程序码。小程序验证原图下载、导出、相册保存及失败分支；未操作用户正在使用的模拟器。

## 体积

引用源码从686,589 B增至693,348 B（应用493,187 B＋第三方200,161 B），增加6,759 B（约6.6 KiB），用于共享绘制、原生 Canvas 导出及卡片样式，无新增依赖或字体/位图资源。明确的新导出功能预算从671 KiB调至678 KiB；以构建报告记录精确源码依赖估算，微信最终上传包需另验。Web海报模块只随服务商页面加载，首屏依赖不增加；性能基线未调整。
