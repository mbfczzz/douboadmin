# 小程序注册与开通

微信登录后，小程序用户按两步开通：

1. **填写资料**：填写姓名和手机号，输入短信验证码完成验证。未完成这一步时，除登录、查询授权状态、发送验证码、提交资料、退出登录外，其他业务接口都返回 `403`，`code=ACTIVATION_REQUIRED`，`access.profileRequired=true`，小程序自动回到授权页。
2. **开通方式**：扫码或输入服务商激活码。后台「小程序用户」页右上角的「开放普通用户注册」开启时，用户也可以选择「跳过，直接使用」，成为不关联服务商的普通用户（后台显示“直接开通”）；关闭后只能用激活码开通。

已开通的老用户下次打开小程序时也需要补完第一步，完成后直接进入，不需要重新激活。关闭开放注册不会影响已经直接开通的用户。

选择跳过的普通用户之后不能再使用激活码（服务端拒绝，小程序里也不再出现授权页）；把普通用户转为服务商关联用户需由管理员处理，暂未提供。

**手机号唯一**：一个手机号只能验证一个账号。已被其他账号验证的号码不能获取验证码、不能完成验证，管理员也不能把它填给其他用户。用户换号并验证新号码后旧号码释放；账号归档（注销）后其号码也会释放。

## 短信验证码

使用阿里云短信服务（`dysmsapi`，标准库实现签名，无额外依赖）。在后台「系统设置 → 接入配置 → 短信验证码」填写，保存后重启服务生效：

| 配置 | 说明 |
| --- | --- |
| AccessKey ID / Secret | RAM 账号需授予短信发送权限（如 `AliyunDysmsFullAccess`） |
| 短信签名 | 阿里云短信控制台审核通过的签名 |
| 验证码模板 CODE | 验证码类模板，内容须包含 `${code}` 变量 |

四项需同时填写。**短信未配置时不强制第一步**（避免先部署、后配置时所有用户无法使用）；保存配置并重启后才开始要求验证手机号。只有开启演示登录的本地开发环境（`ALLOW_DEMO_LOGIN=true`，正式环境禁止）在未配置短信时会强制第一步，并在接口中直接返回 `debugCode` 供调试；该字段不会写入日志。

规则：

- 仅支持中国大陆 11 位手机号；验证码 6 位，5 分钟有效，用后作废。
- 同一用户、同一手机号 60 秒内只能发送一次；同一 IP 每分钟最多 10 次（IP 取自反向代理设置的 `X-Real-IP`）；同一用户、同一手机号每天各最多 10 次。发送失败不计次数，之前收到的验证码仍然有效。阿里云自身的号码频控同样生效。
- 每个验证码最多尝试 5 次（并发提交也逐次计数），超过需重新获取。数据库只保存验证码摘要。
- 手机号只能通过短信验证设置，「我的 → 编辑资料」中不可修改。管理员在后台修改用户手机号（须为大陆 11 位号码）后，用户下次使用时需要重新验证新号码；已填写的姓名和手机号不能被清空。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/access` | 返回授权状态，以及 `profileRequired`、`openSignup`；资料未完成时附带已填的 `name`、`phone` 供预填 |
| POST | `/api/access/sms` | `{phone}`，发送验证码，返回 `expiresIn`、`resendIn` |
| POST | `/api/access/profile` | `{name, phone, code}`，校验验证码并保存姓名和手机号，返回新的授权状态 |
| POST | `/api/access/direct` | 跳过激活码，以普通用户开通；需已完成第一步且开放注册 |
| POST | `/api/access/redeem` | 使用激活码；需已完成第一步 |
| GET / PUT | `/api/admin/signup` | 读取 / 修改「开放普通用户注册」（`{version, openSignup}`）；服务商账号不能修改；默认开放 |

上线前请在微信公众平台更新《小程序隐私保护指引》，声明收集姓名和手机号的用途。
