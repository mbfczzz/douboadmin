# 微信手机号授权登录

默认入口改为微信原生 `getPhoneNumber` 按钮；用户同意后，客户端取得手机号授权 `phoneCode`，再单独调用 `wx.login` 获取登录 `code`，一并交给 `POST /api/auth/wechat`。两个凭证用途不同，不能混用。用户拒绝授权时不会发起登录请求。

## 备用入口与平台边界

登录页和授权页保留「使用其他手机号」，调用原来的微信会话登录，然后按原流程填写姓名、手机号及可选短信验证码。短信验证是否必需仍由后台开关决定。微信原生弹窗内部的「使用其他号码」是微信自己的流程，小程序无法截获该选项并换成自建页面；如果用户在原生弹窗授权其他号码，也会由微信返回手机号授权凭证。

新 API 通过 `/api/config.wechatPhoneLogin` 宣告支持，客户端同时检查原生按钮能力。旧 API 或不支持该按钮的客户端保留原登录入口。授权请求失败后备用入口仍可操作。此功能需小程序在微信后台具备手机号快速验证能力及对应隐私声明，真实授权由微信原生弹窗完成，不能由应用自动代替用户同意。

## 账号与注册

- 保持原有 AppID + OpenID 账号标识，不因授权手机号自动创建另一套身份或合并两个账号。
- 后端使用 AppID/AppSecret 获取服务端 access token，再兑换手机号授权凭证；检查返回的 AppID、国家码与手机号。当前登记继续只支持中国大陆手机号。
- 手机号归属使用既有事务和唯一归属表保护。若已被其他账号验证，拒绝登录绑定，不覆盖他人账号。
- 授权成功只证明手机号归属；姓名仍须填写，服务商扫码登记与审批规则不变。已有已验证号码补填姓名时，在同一事务内确认号码未改变，才允许免除重复短信验证。
- 手动更换手机号不能利用前端的 `smsRequired=false` 绕过后端校验。短信验证关闭时允许未验证登记，但不生成手机号归属证明。
- `phoneCode`、登录凭证与 access token 不存入客户端会话；审计隐藏 `phoneCode` 值。微信错误响应、含凭证的 URL 不透传到用户或日志。

使用现有用户与手机号归属存储，不需要新增数据库表。后端与小程序需共同部署，旧小程序仍可使用原登录接口。

## 验证与包体积

后端验证微信接口契约、token 缓存、错误和 AppID/国家码校验、号码归属冲突、手动登记与审批保护；客户端验证授权拒绝、两个 code 区分、并发登录隔离及手动备用路径。测试均使用隔离模拟，不调用收费的真实手机号接口；仍需微信真机授权验收。
