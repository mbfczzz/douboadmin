# 小程序码直接进入登记（体验版）

用户已选择体验版。配置微信与 OSS 后，后台邀请码、绑定码、会员推广码的图片统一由微信 `getwxacodeunlimit` 生成，页面固定 `pages/activate/index`，`scene` 只携带原来的 8 位邀请码。图片写入私有 OSS；稳定缓存键区分 AppID、目标版本、邀请码及实现版本，重复查看复用图片并刷新签名链接。

流程：微信扫码/识别小程序码 → 打开体验版 → 识别邀请码 → 微信/手机号登录 → 补充原来要求的资料与短信验证 → 自动提交原 `/access/join` 登记 → 等待超级管理员开通。已开通账号按原逻辑进入应用，不自动更换归属。后台校验邀请码有效性、归属、停用、重复登记与审批的逻辑不变。

邀请码暂存在本次小程序进程中，跨登录及填写资料保留；登记成功后清除。失败不会无限自动提交，提供“继续登记”重试；有外部邀请码时不再要求进入小程序二次扫码。未从码进入的用户仍保留输入邀请码/扫描旧二维码作为备用入口。旧印刷普通二维码本身不会变成可直达小程序的码，需要重新下载新图片。

## 启用

1. 部署新 API，保留现有微信 AppID/AppSecret、OSS 配置。`WECHAT_CODE_VERSION=trial` 为本次默认值，可显式设为 `release` 或 `develop`；更换后重启 API。
2. 编译、上传包含 scene 接收逻辑的小程序，并设为体验版。小程序码目标页面必须随包上传。
3. 重新打开后台分享码窗口，下载并重新分发新的小程序码；已有业务邀请码不需要重置。
4. 体验者仍需在微信后台获得体验权限。小程序码不等于公开发布，第三方社交软件不保证直接识别或唤起微信；本次支持微信扫描/识别流程，未实现跨应用 URL Link/Scheme。

微信接口失败时不在生产环境悄悄返回普通二维码。无微信配置的非生产测试保留普通二维码兼容测试；它不具备微信外部直达能力。微信错误和令牌不会透传到日志或客户端。

## 验证及源码体积

微信接口契约、图片解码、非法场景、错误响应、AppID/版本缓存隔离及客户端登录等待/资料等待/失败重试已有隔离回归；未宣称微信真机扫码验收完成。

客户端新增 scene 接收与自动登记模块，源码依赖估算从 684,191 B 增加到 686,589 B（+2,398 B），第三方仍为 200,161 B，无新增依赖。对应明确新功能，上限从 669 KiB 调整到 671 KiB（687,104 B），未刷新性能基线。此值不是微信最终上传包，最终上传包需在开发者工具核验。
