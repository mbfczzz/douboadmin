# 访问统计

管理后台「工作概览 → 访问统计」展示小程序、网页和 APP 的浏览量、访客与来源，可在「全部 / 小程序 / 网页 / APP」之间切换；「全部」另有各端占比。统计匿名进行，与账号、登录状态和「行为分析」授权（`/api/events`）相互独立。管理后台本身的访问不计入。

## 采集内容

### 各端如何上报

| 端 | 上报方式 | `page` 格式 | 来源 |
| --- | --- | --- | --- |
| 小程序 | `POST /api/visits`，不带 `client`（默认小程序） | 页面路由 `pages/…/index` | 微信场景值 `scene` |
| 网页 | 作品分享页 `/s/{token}` 由服务端在返回页面时直接计数，无需脚本；以后的其他网页用 `POST /api/visits` 并带 `"client":"web"` | 路径，如 `/pricing`；所有分享链接合并为 `/s/*`（作品分享页） | `source`：`utm_source` 参数，否则来源网站域名，微信内打开为 `wechat`，否则 `direct` |
| APP | `POST /api/visits` 带 `"client":"app"` | 页面名，字母开头，如 `CreateScreen` | `source`：渠道，如 `appstore`、`huawei` |

分享页使用两个仅限 `/s` 路径的第一方 Cookie 保存随机 ID：`doubo_vid`（访客，1 年）和 `doubo_visit`（访问，闲置 30 分钟过期）。爬虫和链接预览（User-Agent 含 bot、spider、preview 等）不计入；无效或已失效的分享不计入。网页 `platform` 按 User-Agent 识别为 ios、android、windows、mac 或 other。

APP 接入时：首次启动生成随机 `visitorId` 并保存在设备上，每次启动（或后台超过 30 分钟回到前台）生成新的 `visitId`，每个页面显示时上报一次，`platform` 填 `ios`/`android`。其他域名的网页需把域名加入 `WEB_ORIGIN` 才能跨域上报。

同一个人在不同端会被计为不同访客（访客 ID 匿名、按设备生成，不关联账号），因此「全部」的 UV 可能略高于真实人数。「次日留存」按登录账号统计，只在「全部」显示。

### 小程序

小程序每次显示页面时发送一次 `POST /api/visits`（公开接口，不带登录令牌）：

```json
{ "visitId": "…", "visitorId": "…", "page": "pages/create/index", "scene": 1001, "platform": "ios" }
```

- `visitorId`：首次使用时随机生成，保存在本地存储 `visitor-id`；清除小程序数据后会重新生成。
- `visitId`：每次启动随机生成；后台停留超过 30 分钟再回到前台时重新生成。
- `page`：页面路由；`scene`：微信启动场景值；`platform`：`wx.getDeviceInfo().platform`。
- 请求只发一次，超时 3 秒，失败不重试，不阻塞页面。从相册、相机等返回同一页面不重复计数。

服务端校验：`client` 为空、`miniprogram`、`web` 或 `app`；两个 id 为 16–64 位 `[A-Za-z0-9_-]`；`page` 按端校验格式（小程序不超过 60 字符且形如 `pages/…/index`）；`source` 不超过 40 位 `[a-z0-9_.:-]`；`scene` 为 0–99999 的整数；`platform` 不超过 16 位。格式错误返回 400，成功返回 204。同一访问内同一页面 2 秒内的重复上报被忽略。

## 存储

- `visits`：每次访问一条，ID 为 `visitId` 的摘要。记录端（`client`，旧记录为空即小程序）、来源（`source`）、访问日（北京时间）、访客摘要、场景值、平台、入口页、浏览页数、各页面次数（最多 30 个页面）、首末页面时间。`owner_id` 为空，不保存账号 ID，也不保存原始 `visitorId`。
- `visitors`：每个访客摘要一条，记录首次出现日期，用于计算新访客。

开始超过 12 小时的访问不再累加。超过约 400 天的 `visits` 可按 `created_at` 清理；目前没有自动清理任务。

## 指标口径

按访问开始日归入统计周期（北京时间）。

| 指标 | 计算 |
| --- | --- |
| 浏览量 PV | 周期内所有访问的页面显示次数之和 |
| 访客数 UV | 周期内不同访客数；每日 UV 按当日去重 |
| 访问次数 | 周期内访问条数 |
| 人均浏览页数 | PV ÷ 访问次数 |
| 平均访问时长 | 每次访问首末页面间隔的平均值；只看一页的访问记为 0 |
| 跳出率 | 只浏览 1 个页面的访问 ÷ 访问次数 |
| 新访客 | 首次出现日期在周期内的访客数 |
| 次日留存 | 基于登录用户每日活跃（`daily_activity`）：周期内第 D 天活跃且第 D+1 天仍活跃的人次 ÷ 第 D 天活跃人次。只统计 D+1 为已结束自然日的日期 |
| 热门页面 | 按 PV 前 8 个页面，附页面访客数 |
| 入口页面 / 访问来源 / 设备平台 | 按访问次数，分别取前 5 / 前 6 / 全部 |

接口：`GET /api/admin/dashboard` 的 `days[].pv`、`days[].uv` 与 `breakdown.traffic`。比率字段为 0–1 的小数。
