# 删除后重新注册与停用提示

用户端接口区分 `ACCOUNT_DELETED` 和 `ACCOUNT_DISABLED`（均为 HTTP 403）。小程序收到前者会清除旧会话、草稿及视图缓存，回到手机号授权重新注册入口；后者保留明确的停用状态，提示联系管理员，不再显示第 2 步扫码或通用网络重试错误。

微信身份映射原来指向已归档用户时，下次主动登录生成新的用户 ID 并更新凭证关联。原用户记录保持归档，原积分、订单、钱包和服务商权限不迁移到新身份。并发登录在身份锁内共用同一新账号，不重复注册。仅停用、未删除的用户继续拒绝登录，不能通过重新注册绕过停用。

新账号仍按当前规则验证手机号、填写资料和登记授权；如果管理员已为该号码建立新的分公司预绑定，则走既有自动归属流程。旧令牌仍对应旧的已删除账号，不能访问新用户或历史业务。

需部署新版服务端并重新上传小程序。此次不新增数据库字段或迁移。回归覆盖删除后并发注册、停用拒绝、旧会话拒绝、历史钱包保留、前端状态展示、自动清理和迟到响应不清理新会话。

验证通过 Go 全量测试、50 项既有登录测试和 4 项账号状态回归、23 页编译。小程序引用源码依赖估算 723967 字节，原 707 KiB 预算内，无新依赖或预算调整；不是微信最终上传包，最终包仍需上传时核对。

授权刷新交互：未知状态不再默认显示扫码入口；刷新时保留当前错误/状态，成功结果和错误清除在同一次 setData 中提交。刷新失败不自动提交旧邀请码。逐次 setData 的模板条件回归覆盖未知、停用、待审核、正常待登记和重复失败，避免扫码面板闪现；更新后源码依赖估算 723950 字节，原预算内。

再次复查补强：回到重新注册入口时清空旧姓名、手机号、验证码及邀请码输入；过期登录失败响应按会话代次丢弃；钱包示例报价和封面按会话与页面代次校验，隐藏页面或切换账号后不回写。授权刷新防重复点击，检查期间不能启动扫码或输入邀请码。

这部分必要的状态保护新增 684 字节，当前引用源码依赖估算为 724634 字节，比原 707 KiB 上限超出 666 字节。本次明确增加 1 KiB 功能额度至 708 KiB，预算差异随代码保存；无新依赖、图片，未关闭检查或自动重置基线。这是源码依赖估算，微信最终上传包未测量。

最终交叉复查补充：钱包与流水分批返回期间切换账号，聚合结果也会再次核对所属用户，避免写入旧余额。新增账号状态和刷新回归已纳入 `npm run test:auth`，后续按常规登录测试即可覆盖。

交叉复查发现并修复旧表单跨会话重放：注册资料、发短信、提交邀请码共用 `registerRequest`，写入前核对页面 userId 和当前 token。会话过期或已换用户时加载当前登录状态后返回，不启动自动登录后继续旧提交；换 userId 清空旧资料和邀请码，同一用户续期 token 保留未完成输入。新增 10 项确定性回归纳入常规登录测试（合计 72 项）。服务端微信登录签发 token 前的最终检查也补齐删除/停用的明确状态码，新增竞态测试。

最终源代码依赖估算为 725322 字节，应用源码 525161 字节、引用 SDK 源码 200161 字节。绑定提交身份和表单清理复用代码增加 688 字节，超出 708 KiB 额度 330 字节，因此此项再明确增加 1 KiB 至 709 KiB；无新运行时依赖、图片，不改变 Web 包或跳过检查。最终微信上传包未测量。
