# 多图生成结果

图片模型返回多个独立结果地址时（例如 Midjourney 返回 4 张），完整保留其顺序并分别保存到 OSS/本地媒体存储。任务仍是一条，按原任务价格结算一次。

- 任务详情：多图以两列网格展示，点击指定图片进入可左右切换的预览；每张可单独保存，底部支持保存全部。单张图保持原展示方式。
- 作品列表和最近完成列表：第一张作为封面，并标注图片数量。
- 小程序分享页及网页分享链接：展示全部图片；删除作品后整组分享失效。
- 下载前刷新过期签名；批量保存中断时说明已保存数量，可单独保存剩余图片。

后端识别 `output_urls`、`data[].url`、嵌套 `result.images` 等结果容器以及 base64 图片。输入回显、缩略图不作为生成结果；不将单张四宫格合成图自动切割为四张。仅返回一个图片地址时仍按单张处理。

多图在既有任务/执行记录的 result 字段内存储有序 JSON 数组。单张结果保持原字符串格式，无新增数据库字段。对外 API 的 `result` 保留第一张 URL，新增 `results` 数组，旧版客户端仍可读取封面。下载失败时保存阶段重试，已存图片复用稳定的独立资源 ID，避免重复提交上游。

需更新 API、worker 和小程序。之前已经只保存第一张的历史任务不会凭空恢复其他图片。

## 源码依赖预算

改动前（含画质/清晰度隐藏修复）引用源码依赖估算为 744,454 字节；多图实现及复核修复后为 752,011 字节，增加 7,557 字节（约 7.38 KiB）。业务源码从 544,293 增至 551,850 字节，第三方引用仍为 200,161 字节。一个共享原生组件用于三个页面，保存与签名刷新复用同一模块，未新增 SDK 组件、依赖或图片资源。

既有 728 KiB 上限仅剩约 1 KiB，无法容纳此次完整多图功能；为这项明确功能增量将源码预算调整至 736 KiB，保留文件长度、编译和预算检查。该值是源码依赖估算，并非微信最终上传包；最终包需在微信开发者工具上传时另行核对。

## 复核修复

- 同时返回单张封面和多图结果时，优先读取完整结果容器，避免仍只保存封面。
- 将旧版缓存的单图任务转换为新版图片数组，离线首屏仍可显示。
- 图片缓存只忽略 OSS 签名字段，保留图片 ID、缩放等业务参数，避免误用另一张图片；按账号隔离缓存记录。
- 离开页面后不再弹出迟到的预览或继续写入相册；重复预览点击不重复发起刷新。

复核验证：74 项小程序测试、23 页原生编译、Go 全量测试与 vet 通过。浏览器布局投影已检查 320/390/430px，尚未进行真实微信设备和真实 Midjourney 返回结果的联调。
