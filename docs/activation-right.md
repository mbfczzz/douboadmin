# 下级小程序开通权限与角色名称

## 角色名称

| 内部编码 | 显示名称 |
|---|---|
| super_admin | 超级管理员 |
| branch | 分公司 |
| s1 | 一级服务商（原“S1 服务商”） |
| s2 | 二级服务商（原“S2 推荐官”） |
| member | 合伙人（原“会员”） |

只改显示名称，内部编码、层级、数据和分佣规则不变。“角色管理”中仍保存为旧默认名称的系统角色，自动显示新名称；在“角色管理”里手动改过的名称保持不变。邀请码同步改名：一级服务商邀请码、二级服务商邀请码、合伙人开通码。

## 下级小程序开通权限开关

- 适用对象：分公司、一级服务商、二级服务商。合伙人没有该开关。
- 只能由超级管理员在后台“服务商管理”中，对每个主体单独设置（行内按钮“下级开通：开 / 关”）。默认关闭，互不影响，不随上下级继承。
- 存储：`partners.activateChildren`；接口 `PUT /api/admin/partners/{id}/activation`（仅超级管理员）。每次切换写入服务商审计日志。

| 开关 | 效果 |
|---|---|
| 关闭 | 该主体名下的登记只能由超级管理员开通或拒绝，该主体看不到、也处理不了这些登记（与之前完全一致） |
| 开启 | 该主体可以在后台开通或拒绝自己名下整条线的登记，包括直属和间接下级 |

开启后可开通的范围：

- 分公司：名下的一级服务商、二级服务商、合伙人
- 一级服务商：名下的二级服务商、合伙人
- 二级服务商：名下的合伙人

附加条件：该主体自身及其上级链条都必须处于“已开通”状态，否则开关开启也不能操作。每次开通、拒绝都会逐条校验开关和层级，并记录操作人。

服务商登录后台后：开关开启时，待开通的下级行显示“开通 / 拒绝”，各级行提供“合伙人登记”入口；开关关闭时显示“等待审核开通”。

小程序与后台的提示语统一为“审核开通后生效”，不再写“超级管理员开通”。
