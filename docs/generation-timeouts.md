# 生成任务总超时

- 图片任务：从任务创建起最多 10 分钟。
- 视频与混剪任务：从任务创建起最多 1 小时。
- 总时间包含排队、提交、轮询上游以及下载保存结果，不随重试、更新时间或阶段切换重新计时。

worker 启动后立即扫描既有任务，之后每秒扫描一批最多 100 条；正常数据库负载下，达到期限后会在下一次扫描转为失败，显示明确的图片/视频超时原因。即便任务仍持有租约，也会使旧租约失效，迟到的结果、续租和进度更新不能恢复成功状态。数据库不可用时需等待存储恢复后才能持久化状态。

每轮 worker 调用的上下文也受剩余总时间限制。provider 在超时后不再提交、查询或保存结果，保存阶段不再独立等待一小时。管理员不能恢复已超过总期限的原任务，需要重新创作。聊天、音频和素材导入维持既有规则。

## 积分

超时改变任务状态，不视为“上游确认未生成”。沿用既有结算核实规则：尚未提交上游或上游已明确失败时释放预留积分；存在提交、轮询、已生成但未保存等未核实状态时保留预留积分，由管理员核实后使用现有“退回积分”操作处理。超时扫描不会自动重新生成或重复扣费，重复扫描也不会重复退款或发通知。失败状态和积分、通知更新在同一事务中完成。

## 部署及验证

部署 API、worker 和后台；无需数据库结构迁移。新 worker 会处理此前已经超过期限的排队/生成中任务，不需要重新提交任务。仅更新前端无法让服务端任务超时。

回归覆盖 10 分钟/1 小时边界、已有任务启动清理、排队与活动租约、保存结果阶段、迟到完成、并发扫描、结算和通知幂等，以及运行中列表的真实状态。MySQL 分支使用相同截止时间与事务规则；真实 MySQL 集成环境需通过 `MYSQL_TEST_DSN` 指向专用测试库，当前未连接线上数据库验证。
