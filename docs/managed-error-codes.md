# Managed 业务错误码与小程序提示

依据 2026-11-16 `https://managed.tcmzhan.com/` 登录后的「客户接口文档」。Managed 错误结构为 `error.code` 固定整数、`error.type` 固定类型、`error.user_message` 可展示提示；供应商原始代码与类型仅供管理排查。客户端按 code 分支，不匹配 message。

|---:|---|---|---|

服务端解析提交错误和任务查询错误，将业务码、类型、用户提示、处理建议及重试属性保存在 `executions`。用户任务接口返回 `errorCode`、`errorType`、`errorAction`、`retryable` 和 `editable`；原始 message、upstream_code、upstream_type 只保留在管理排查信息中。模型自定义错误提示仍可覆盖用户提示，但不改变业务码、处理建议或具体原因。

小程序任务列表在失败原因后显示错误码；任务详情同时显示处理建议。未知业务码显示通用安全提示和原始数字码，不展示上游原始文本。5007、5011、5202 不允许盲目重新生成；可明确重新提交的错误才显示“重新生成”。

异步受理前的 5007、5011、5202 作为结果未知保存，避免释放积分后换幂等键重发；查询原任务明确返回终态错误时按码结束任务。SSE 流内错误不保证有整数业务码，本次非流式生成链路不依赖 SSE 映射。

新增执行记录字段由既有数据库迁移自动补列，无需手工 SQL。部署新版服务端后执行迁移，再上传新版小程序。
