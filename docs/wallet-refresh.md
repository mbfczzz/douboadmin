# 我的积分刷新时机

按用户最终要求，移除预留积分触发的定时刷新及后台余额检查。即使存在长期预留积分，停留在页面上也不会定时请求钱包或流水，不再重复重建套餐图片。

每次进入或返回“我的积分”页面，onShow 读取一次最新余额和流水。手动点击刷新、下拉刷新、翻页和支付确认完成后的更新保留。支付中的订单状态校验保持独立，不将原生支付成功回调当作实际到账。

没有新增依赖或图片，取消上一方案的监测模块，此项修改不增加源码预算；账号状态功能的独立增量见 account-lifecycle.md。源码依赖估算与微信最终上传包分开核对；本次未获取微信最终上传包。

## 用户看到的积分（不再出现“预留”）

提交创作时积分直接从“可用积分”扣除，生成失败自动退回；用户界面不再出现“预留 / 冻结 / 结算”。

- 我的积分、我的页余额行、积分组件：只显示可用积分，去掉“预留 X 积分 · 处理中暂时冻结”。
- 积分明细：提交显示“生成扣除 -X”，失败显示“失败退回 +X”；成功时的内部结算（不改变可用积分）不再列出（`GET /api/wallet/ledger` 对用户过滤 `availableDelta = 0` 的流水，后台明细仍完整）。
- 任务详情：已扣除 / 已退回；积分确认弹窗写“提交后扣除，生成失败自动退回”；积分说明改为“提交创作 → 扣除积分；生成失败 → 自动退回”。
- 服务端发给用户的文案去掉“预留”（如“任务积分已退回”）。

记账方式不变：内部仍先记为处理中、成功后结算、失败退回，后台的积分流水和用户详情保留“预留”字段供核对。
