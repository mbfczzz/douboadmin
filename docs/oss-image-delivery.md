# 图片通过 OSS HTTPS 加载

## 本次落地

- 已用现有 OSS 配置将 26 张内置模型图和 1 张项目 Logo 同步到 `douboai-test`；使用内容哈希键，逐张 GET 并解码 PNG 验证，27 张全部通过。不修改桶 ACL，不把签名地址写死进代码。
- 登录/授权页独立请求 `/api/branding`，拿到 HTTPS 图标才渲染，取消初始化及失败时的 HTTP `/api/brand-icon` 请求。图片失败显示品牌名称并可重试，不阻塞登录和授权。
- `/api/branding` 增加已完成 OSS 同步的 `modelIcons` 映射；后台 Logo、favicon、模型目录和图标选择器使用这些 HTTPS 地址。原模型配置仍保存稳定的图标标识，不存过期签名。未同步或签名失败不返回伪造 URL。
- 推广码、邀请码、绑定码 PNG 按内容哈希写入私有 OSS，重复读取复用对象并重新签名。小程序保存二维码支持 HTTPS 下载及旧版 base64，下载失败不调用保存相册。
- 头像、素材、模板上传封面、生成结果沿用现有私有 OSS 上传/签名链路；缩略图由 OSS 图片处理或视频截帧生成。

## 已核验与边界

当前 `.env.local` 对应数据库只读核验：17 条素材，没有遗留本地 URL；20 条活动模板全部关联封面资产，无外链封面；热门视频及缓存无记录。没有下载或上传测试 fixture、调用收费热门视频接口、生成新业务二维码。

已有上传资源无需重传。当前线上 `/api/branding` 已返回 OSS HTTPS Logo；新后台模型映射与二维码能力需部署新 API，客户端修复需重新编译/上传小程序。未在本轮重启远端服务或上传体验版。

内置图片签名有效期 24 小时；用户素材和二维码使用短期签名。客户端重新获取接口时刷新链接，不持久保存签名。保持桶私有，不把 AccessKey 放入前端。微信后台需配置实际使用的 OSS 域名，二维码下载使用 downloadFile 合法域名。

模板未来若直接填写外部封面 URL，或以后启用第三方热门视频封面，现有接口仍允许来源方 HTTPS 地址；这类入口尚未增加自动导入 OSS，不应把本次核验称为所有第三方资源已迁移。当前实际数据没有此类待迁移项。
