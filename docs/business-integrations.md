# 支付、数据与通知的可配置接入

微信登录、虚拟支付、OSS、视频站点、订阅消息和告警可在「系统设置 → 服务接入配置」加密保存到数据库，填写步骤和备份规则见[后台接入配置](admin-integration-settings.md)。修改连接配置后重启 API 与 Worker，业务规则仍在后台保存即生效。环境配置继续兼容：本地使用 Git 忽略的 `.env.local`，原生部署使用 `/etc/doubo/doubo.env`。不要将服务密钥放入小程序、构建包或接口响应。

| 能力 | 配置 | 未配置时的表现 |
| --- | --- | --- |
| 微信支付 APIv3 | WECHAT_APP_ID、WECHAT_PAY_MCH_ID、WECHAT_PAY_CERT_SERIAL、WECHAT_PAY_API_V3_KEY、WECHAT_PAY_PRIVATE_KEY_PATH、WECHAT_PAY_PUBLIC_KEY_ID、WECHAT_PAY_PUBLIC_KEY_PATH、WECHAT_PAY_NOTIFY_URL、WECHAT_PAY_REFUND_NOTIFY_URL | 不创建充值订单、不调用支付；已有积分账本仍可用 |
| 第三方资源配置（TikHub，可在后台设置） | TIKHUB_BASE_URL 默认 https://api.tikhub.io，TIKHUB_API_KEY，HOT_FEED_SOURCE（search / billboard），HOT_FEED_KEYWORDS，HOT_CACHE_*_MINUTES | 热门视频页面提示未配置，提供上传自有素材入口 |
| 完成订阅消息 | WECHAT_COMPLETION_TEMPLATE_ID、WECHAT_COMPLETION_FIELDS | 仍保存站内通知，不申请未配置的订阅模板 |
| 外部异常通知 | ALERT_WEBHOOK_URL | 告警仍可在后台查看 |
| 公网分享 | PUBLIC_BASE_URL=https://实际域名 | 可访问小程序分享页，本地短链不宣称可公网访问 |

## 微信支付

1. 先确认商户与小程序关联、业务类目及积分业务获准使用的支付产品。普通商户 APIv3 JSAPI 与[微信虚拟支付](virtual-payment.md)均有独立实现，不能只替换商户号。iOS 默认关闭。
2. 将商户私钥及微信支付公钥放在服务端只读路径。Docker 对应 `deploy/secrets/` → `/run/secrets/`；公开密钥 ID 与文件应配套，APIv3 密钥长度 32 字符。
3. 设置通知地址 `https://实际域名/api/payments/wechat/notify` 和退款地址 `https://实际域名/api/payments/wechat/refund-notify`；需真实公网 HTTPS。
4. 重启后在后台确认“微信支付：已配置”，并检查积分套餐的商品 ID、售价和到账积分。充值由支付通道配置决定，生成按模型定价扣费；原业务设置的兑换率、充值范围及开关已移除。
5. 真机小额验收：支付成功/取消/断网、重复通知、查单补到账、全额退款。没有真实商户凭证时，只能验证协议与账本测试，不能标记实付通过。

每元积分兑换在订单创建时固定。充值到账、生成扣减和退款均有可追溯流水。管理后台退款页显示的是最终可信状态，申请受理不等于退款成功。自动补单按共享游标轮询未结算记录，故障订单不会挡住后续查询。

### 小程序充值与创作积分

- 「我的」「创作」「任务详情」显示服务端实际可用积分、预留积分，并提供积分/充值入口。回到页面会重新读取；存在预留时每 3 秒刷新，其他情况每 15 秒刷新，离开页面停止。
- 「我的积分」输入金额后调用微信支付。支付窗口成功只表示提交完成，必须等服务端验签通知或查单确认后才显示「积分已到账」。到账确认中禁止再次发起同一轮充值；退出页面后返回会继续查询。
- 待确认状态按用户和订单分别保存，兼容旧版单笔记录。订单列表分别确认多笔订单，结算一笔不会清除另一笔；待确认订单不会再次打开支付窗口。新支付取消后清除上一笔成功提示。
- 钱包页存在预留积分时每 3 秒重新读取余额及流水，任务成功、失败退回或退款结算后自动更新；预留清零或离开页面后停止刷新。积分卡片返回后可继续打开钱包，连续快速点击仍防重。
- 支付后短暂断网保留订单，不在本地虚增余额；可以在充值订单查看结果。取消支付保留未支付订单供继续支付，过期订单不再显示继续支付按钮。
- 创作前校验模型参数并确认积分；提交任务时从可用积分中预留，成功后结算预留，明确失败则退回。上游结果未知时仍保留预留，交由对账或管理员核实，不能直接当作失败退款。
- 示例：余额 1000 积分，提交 25 积分任务后显示可用 975、预留 25；成功后显示可用 975、预留 0；失败退回后可用恢复 1000。积分流水中的「结算」不是再次扣可用余额。
- 管理后台必须分别开启「充值」和「生成扣费」，并配置模型积分。模型档位留空使用基础积分，显式填写 0 表示免费。小程序直接申请开通的普通用户与服务商激活用户均可按规则消费积分。

隔离回归：在 `miniprogram` 运行 `npm run test:payment`；在 `server` 运行 `go test ./internal/api ./internal/billing ./internal/payments ./internal/store`。API 支付链路用测试RSA密钥和加密签名通知验证到账及幂等，不产生真实付款。MySQL跨实例测试需要单独的 `MYSQL_TEST_DSN`，不会自动使用业务数据库。

## 抖音

TikHub 适配已核对其 OpenAPI：搜索 `POST /api/v1/douyin/search/fetch_video_search_v2`，详情 `fetch_one_video`，热词 `fetch_hot_search_list`。后端缓存上游结果；播放量仅对返回页面内已提供数据排序。账号实际权限、数据字段与下载链接需要凭证到位后验证。

创作页视频流：默认按关键词搜索 `POST /api/v1/douyin/search/fetch_video_search_v2`（每个创作页关键词一页一页取，「热门」也按这个词搜索）；「第三方资源配置」中的视频来源（`HOT_FEED_SOURCE`）可改为抖音视频热榜 `POST /api/v1/douyin/billboard/fetch_hot_total_video_list`（`HOT_FEED_SOURCE=billboard`：近 7 天、视频总榜 `sub_type=1001`，每页 20 条，按标签关键词过滤，「热门」不过滤；重启生效），两种来源分开缓存。热榜接口 TikHub 未写明返回格式，解析兼容 `objs` / `list` 等常见结构，读不懂时记 `tikhub billboard reply not understood` 警告并附返回开头。创作关键词在「第三方资源配置」中设置（`HOT_FEED_KEYWORDS`）（重启生效；经 `GET /api/hot/discovery?words=0` 下发）。首页结果存 Redis（`doubo:hot:feed:*`），默认有效 1 天（`HOT_CACHE_FEED_MINUTES`）；API 进程每分钟检查，到期前 1 分钟提前刷新，多实例用 Redis 锁保证每个关键词只刷新一次；刷新失败保留旧数据（最长 2 倍时长）并在下一分钟重试，失败写入 `hot feed refresh failed` 警告日志。后面的页超过有效期会重新读取，TikHub 失败时才用旧页。封面是抖音 CDN 地址，若出现封面过期打不开，把这个时长调短。未配置 Redis 时退回数据库缓存。

一键复刻视频拆解：后台「服务接入配置 → 视频理解」配置 OpenAI 兼容的视频理解接口（默认火山方舟 `https://ark.cn-beijing.volces.com/api/v3`，模型 `doubao-seed-2-1-lite-260915`（豆包 Seed 2.1 lite，原生支持视频理解；旧的 1.6 vision 已下线））。复刻在任务队列中进行：复刻页以 `POST /api/hot/videos/{id}/import`（`purpose=remake`，附用户替换图片、原视频标题/文案/时长）创建导入任务，Worker 先把无水印原视频存入用户素材（作者原始上传不是 MP4 时，例如 iPhone 的 .mov，改存抖音的无水印播放版；图文作品没有视频，复刻页直接提示换一条，任务也会以明确原因失败），再调用 `chat/completions` 拆解：50 MB 以内用 OSS 签名地址（`video_url.url`，已知时长且不超过 5 分钟时 fps=2，否则 fps=1，方舟 URL 方式上限 50 MB）；50–512 MB 由服务器从 OSS 流式读取，经方舟 Files API（`POST /files`，`purpose=user_data`，`preprocess_configs[video][fps]` 同上，`expire_at` 一天后）上传，轮询 `GET /files/{id}` 至 `active` 后以 `video_url.file_id` 拆解，结束即 `DELETE /files/{id}`；超过 512 MB 不拆解。Files API 仅火山方舟支持，「视频理解」改用其他兼容接口时大视频会拆解失败，输出可替换的主体（1–5 个人物或商品：称呼、外观、出现时间；不写真实姓名，分镜中提到它们时写成【称呼】，替换只改带括号的称呼；分镜的台词/口播与只显示在画面上的文字分开，后者不写进生成描述）、钩子、结构、卖点、风格、音乐和 3–12 个分镜。视频理解模型未配置、未开通或无权限（401/403/404）时，自动改用后台已开通的豆包对话模型拆解（豆包能直接看视频）。结果按「模型 + 抖音视频 ID」存入 `hot_breakdowns` 表（v2 起含主体；v3 起人物用固定称呼，新复刻会重新拆解一次，已就绪的旧任务仍读取 v2 结果）并全员共用；同一视频并发准备时只调用一次模型，其余等待其结果；失败或超过 20 分钟未完成的可重新发起（大视频要先上传），且只能用该视频本身的保存副本发起（抖音视频看素材的 `sourceVideoId`，上传视频即其本身）。任务就绪后，任务详情「生成同款」读取 `GET /api/hot/videos/{id}/breakdown`，自动选支持参考视频的模型、最接近原视频的时长和最接近原视频的画面比例（尺寸由服务器从 MP4 文件头读取并记入素材的 width/height，含手机竖拍旋转；旧素材首次用时以分段请求读取文件头），由服务器 `POST /api/remake/prompt` 按拆解结果写出分时段描述（覆盖全部分镜，超长时平均缩短各镜头描写、台词保留；按分镜自身的时间跨度铺满生成时长；被替换主体在每个镜头中直接写成 @图片N、外观以图片为准，未替换的保持原样；有替换时描述先固定原视频（比例、机位与运镜、构图、动作顺序与速度、场景与光线，不新增特效和镜头），再「仅将@视频1中的X替换为@图片N中的人物」，并逐项锁定：人物身份（附图片长相描述）、服装（有商品替换时以商品为准）、接替全部动作、手中道具、站位与构图、光影融合、质感与台词；原人物只写称呼不写外貌，替换图片由视觉模型读一次长相（人物的脸型、五官、发型、肤色，商品的外观），写进「换成@图片N中的人物（……）」并缓存在素材的 looks 上；不要字幕和水印；拆解已更新、替换对不上时返回 409，任务页重新读取主体），确认积分后直接提交视频生成。拆解失败、拆解较旧（v2，镜头里没有【称呼】）或没认出可替换的人物和商品时，任务页提示并提供「重新拆解」（只对这几种情况真正重跑，且距上次完成至少 5 分钟；等待时读取 `?fresh=1` 的本次结果）；「生成同款」的模型默认排在前面的是能同时带图片、可带图片最多的模型；没有拆解时描述以 @视频1 的画面为准（上传视频的默认标题不作为主题）；拆解因网络没读到时提示「重新读取」，生成同款不受影响（服务器自行读取拆解）。用户上传了图片时，任务页按拆解出的主体逐个选择「用哪张图替换 / 原样」（默认把图片按顺序配给人物和商品），描述里写明「主角＝@图片1中的人物」并替换进对应镜头，只发送被选中的图片；出镜最多的人物未替换时提示成片会接近原视频；「调整后再生成」打开编辑页复刻预设。未配置、失败或视频过大时复刻照常进行，只参考视频文案。拆解费用由平台承担。

一键复刻也可以**上传手机里的视频**：`POST /api/remake/upload {video, assets, title, duration}` 建同样的准备任务，来源为 `u<素材ID>`，准备时直接使用该素材、不经 TikHub 下载，拆解结果只有上传者本人可读（`GET /api/hot/videos/u<素材ID>/breakdown`）。未选择视频时，复刻页下方展示创作页关键词下的热门视频（每个关键词 6 条，读共享缓存），点一下即载入复刻。

分享链接与无水印原视频（文案提取、一键复刻）：

- 分享链接：链接里已带作品 ID 时直接用详情接口；短链接（`v.douyin.com`）交给 `GET /api/v1/douyin/app/v3/fetch_one_video_by_share_url`，返回空时按 TikHub 说明改用同参数的 `web/fetch_one_video_by_share_url`。服务端自身不打开用户粘贴的地址，只接受抖音域名。`filter_list[0].reason` 为 5 / 10 / 8 时分别提示私密、部分可见、删除或版权受限（不可用结果同样计费）。
- 无水印原视频：导入素材（`POST /api/hot/videos/{id}/import`）先调 `GET /api/v1/douyin/app/v3/fetch_video_high_quality_play_url?aweme_id=…&region=CN` 取原始上传画质（每次约 0.005 美元，`region=CN` 返回国内 CDN）；蓝 V 账号与投流作品不支持原画，此时改用详情里的 `play_addr`（跳过带水印的 `playwm` 地址）。

### TikHub 缓存（后台可配置）

「系统设置 → 第三方资源配置」中的四个时长（分钟，重启生效）决定 TikHub 结果复用多久；未保存过该分组时使用环境文件配置：

| 配置项 | 默认 | 范围 | 用在 |
| --- | --- | --- | --- |
| `HOT_CACHE_FEED_MINUTES` 创作页视频流 | 1440 | 5–1440 | 创作页视频流（Redis，到期前 1 分钟后台刷新，旧数据最多保留 2 倍时长；无 Redis 时存数据库） |
| `HOT_CACHE_SEARCH_MINUTES` 搜索结果 | 5 | 1–1440 | 热门视频页的关键词搜索（按关键词、排序、翻页分开缓存） |
| `HOT_CACHE_WORDS_MINUTES` 热门搜索词 | 10 | 1–1440 | 热门视频页的抖音热词 |
| `HOT_CACHE_VIDEO_MINUTES` 视频详情与链接解析 | 30 | 1–720 | 视频详情页、文案提取和一键复刻粘贴链接读取视频（同一链接在时长内不再解析，表 `hot_links`） |

始终实时调用、不走缓存的：导入素材和一键复刻准备时读取视频详情（要新鲜的播放地址下载）、取无水印原画（签名地址会过期）。搜索新拉到的结果会顺便存下每条视频，点进详情页时在有效期内不再请求 TikHub；命中缓存的搜索页不再重复写库。

搜索 V2 按[官方返回结构](https://docs.tikhub.io/370212780e0)读取 `business_data[].data.aweme_info`，兼容条目 `data` 为对象或 JSON 字符串，以及既有 `data[]` / `aweme_list[]` 格式。视频编号和计数按原始数字精度解析，保留真实的 0 与缺失指标区别；非视频卡片跳过，正常空列表返回成功，上游业务失败或格式错误不伪装为空列表、不写入缓存。分页优先读取顶层字段，并兼容业务配置中的分页信息。此修复仅需更新 API，无需更新小程序或修改数据库；本地协议与接口回归使用模拟上游，线上完整回归需部署后通过已登录的小程序执行。

## 混剪界面与通知

小程序混剪界面保留，生成服务暂未开放。后台音乐管理、混剪专用配置及服务器视频合成代码已移除。

WECHAT_COMPLETION_FIELDS 为 JSON 对象，键名来自获批模板，值可使用 `{{title}}`、`{{jobId}}`、`{{state}}`、`{{time}}`。用户在“设置”主动授权后才尝试发送。微信拒绝或网络结果未知会记录失败/未确认，不盲目重复发送；获取 access token 失败可以重试。站内通知和微信订阅待发送记录在任务事务中独立生成，两个偏好互不影响；推送通过游标读取最近 24 小时未尝试发送的记录，不受站内消息列表上限影响。

生产配置、域名、OSS/CDN、备案与提审待办见 [release-checklist.md](release-checklist.md)。
