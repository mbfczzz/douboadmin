# 工作概览积分统计

所有金额以积分的百分之一存储、以积分展示。期间按北京时间划分，跟随「今天 / 近 7 天 / 近 30 天 / 近 90 天」。

| 指标 | 口径 |
| --- | --- |
| 已使用积分 | 任务成功、计费记录已结算，且存在对应的真实扣费流水；按流水结算时间归属期间 |
| 图片已用积分 | 已使用积分中的图片任务 |
| 视频已用积分 | 已使用积分中的视频、混剪任务 |
| Agent／其他已用积分 | 已使用积分中的对话、配音等其他任务；不含素材导入 |
| 当前待结算积分 | 所有仍为预留状态的任务积分，含排队、生成中和等待核实的失败任务；是当前快照，不受所选期间限制 |
| 失败已退回积分 | 期间内实际退回到账的失败任务积分，含自动退回和管理员人工退回 |

已使用积分不计提交预扣、未结算任务、失败任务、免费任务或仅有报价但没有扣费流水的任务。对话按量计费使用结算后的净扣费，不把返还的预留差额算作消耗或失败退回。图片、视频和其他三项之和等于已使用积分。

结算依据为 `job_billing`、任务最终状态与 `wallet_ledger` 的核对，不取现价、任务报价或任务更新时间。顶部「积分消耗」、按日／小时趋势和上期对比采用同一结算时间口径。生成次数和成功率仍按期间发起的任务统计。

MySQL 在同一个只读一致性快照中读取账本与任务；补查期间前提交、期间内结算的任务，以及更早的未结算预留，按 200 个 ID 分批读取，无近期任务条数截断。现有表结构即可使用，无需数据库迁移；上线需同时部署 API 与后台网页。

回归覆盖跨北京时间零点、跨期提交与结算、按量净扣费、预留、失败自动／人工退回、无流水与异常状态排除，以及桌面和窄屏展示。真实 MySQL 回归由专用 `_test` 数据库的 `MYSQL_TEST_DSN` 启用，不应连接业务数据库运行。
