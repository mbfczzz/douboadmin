# 模型管理的中转余额

模型目录顶部、拖动排序按钮之前显示“中转余额 N 积分”。页面首次打开时读取，点击旁边刷新按钮只重新查询余额；右上角“刷新”同时刷新模型列表和余额。切换模型类型、搜索或分页不会重复查询余额，不自动轮询。离开页面取消未完成请求。

通过服务端 `GET /api/admin/models/balance` 使用既有中转客户端查询 `GET /v1/balance`，请求不带 body 或 model。仅超级管理员可读取，客户 Key 不返回浏览器。余额查询不调用模型生成或任务扣费接口。

中转服务接入地址应指向 Managed 层，包含其部署前缀。例如接入地址为 `https://managed.tcmzhan.com/managed` 时，实际查询 `https://managed.tcmzhan.com/managed/v1/balance`；沿用同一客户 Key，不尝试查询底层 Relay 或自动切换到其他地址。

接受数值 balance（包括 0），且 unit 必须为 points，显示最多六位小数。使用 GET 只读查询，不在本站缓存；返回 `Cache-Control: no-store` 和本次查询时间。数字表示该客户 Key 共享的 Managed 可用余额，已扣除进行中任务预扣，并非本站小程序用户钱包余额。

服务端查询最多等待 8 秒。未配置、Key 无效/停用、不支持该接口或上游失败时显示“查询失败”，悬停提示原因，并可重试；不伪造 0，也不把上游 Key 的 401 当成后台管理员退出登录。只有成功响应格式正确才显示余额。

需部署 API 和管理后台，无需数据库迁移或更新小程序。本地验证使用隔离接口模拟，没有读取或修改真实中转账户余额。
