# 从 FlowLight 导入视频模板

后台“创作模板 → 导入模板”选择 FlowLight 管理端“导出全部模板”生成的 v1 JSON 文件。先预检，再点击“导入已通过的模板”。默认保存为草稿，更新小程序后再上架；勾选“按原文件上架状态导入”时，仅原本已上架的条目会发布。仅超级管理员可访问接口。

导入视频模板；图片条目明确跳过。按上游模型标识匹配本项目模型，不按显示名称匹配，不自动更换默认模型。保留完整提示词、分类、风格/灵感类别、时长、画幅、清晰度、图片用途及选填位置、可选模型和上传说明。模型缺失或规格不匹配会列出原因。来源为未配置默认模型的草稿时，可以先导入草稿再配置。不会复制模型价格或改动测试环境已有定价。

封面和预览使用来源站点的 HTTPS 链接，相对路径根据文件的 `sourceOrigin` 解析；不生成作品，不复制图片/视频文件，不发起模型付费调用。需要与生产素材完全独立时，可在导入后通过现有封面上传功能重新存储素材。

模板编号由来源站点和原编号生成稳定散列。重复导入保留本地已有记录，包括本地编辑及删除决定，不覆盖内容或重复创建。已成功的条目无需重做，失败条目可重试。接口逐条保存并返回结果，不承诺跨所有条目的单一事务；部分失败会明确计数。预检不写入模板。

## 配方与图片位置

模板提示词上限为 20,000 字，图片位置最多 16 个，实际图片数量仍受模型能力及平台单次素材上限约束。每个位置保留用途和必填/选填属性。请求中 `imageSlots` 与 `assets` 一一对应；缺少必填位置、重复位置或重复素材在生成前拒绝。`{{image:N}}` 在服务端根据实际上传顺序替换为对应图片编号，未上传的选填图片明确标记为未提供，不用其他图片顶替。

迁移模板的私有提示词不通过用户模板列表、详情或任务接口公开。生成时由服务端读取已发布模板配方，不信任客户端传入的提示词。原有模板流程保持兼容。更换可选模型及清晰度后重新报价，最终仍按当前模型配置、积分确认和素材归属规则校验。可选模型不限于模板保存的“可选生成模型”：所有已上架、支持模板时长（如 30 秒）与画幅、支持模板生成方式（图生视频/首尾帧在模型有全能参考时按全能参考）且能接收参考图的视频模型都可选，按后台模型排序显示，进入时选中列表第一个；服务端按同一规则（`Template.AcceptsModel`）校验。

## 接口与部署

- `POST /api/admin/templates/import-preview`：读取 `{pack, publish}` 并返回预检结果。
- `POST /api/admin/templates/import`：按同一格式导入通过校验的条目。
- 单次请求最多 8 MiB、2,000 条，检查格式版本、数量和来源编号，拒绝不完整文件。

部署前执行项目现有 `migrate` 流程，为 `templates` 增加 `imageSlots`、`selectableModels` 两个 JSON 列及 `inputHint` 文本列；原有模板字段不改。随后更新 API、Worker 和管理后台，并更新小程序。旧 API 对预检接口返回 404/405，后台会提示先部署新版 API。旧小程序不支持明确的图片位置，不能用它验收新增的选填配方。

2026-11-17 对用户提供的 109 条导出文件和测试环境模型快照进行隔离演练：103 条视频预检及保存成功，6 条图片跳过；第二次导入识别 103 条已有记录，原有 20 条模板保持不变。演练使用内存存储，没有修改测试数据库或创建生成任务。实际导入仍须在部署新版服务后执行。

## 小程序体积

新增配方图片位置、选填上传、模型/清晰度选择及状态隔离，复用现有 SDK。合入 `172d539` 后，LF 标准化引用源码估算从 780,282 B 增至 791,241 B（+10,959 B），引用第三方源码仍为 200,161 B。为这项明确功能将预算从 762 KiB 调整为 774 KiB；这不是微信最终上传包体积，最终包仍由开发者工具验证。

模型 / 清晰度选择由原生 `picker`（系统白色滚轮）改为页面内深色行 + 底部选项面板（复用 `t-popup` 与现有面板样式，无新组件），源码估算 791,241 B → 793,140 B（+1,899 B），预算 774 → 776 KiB。
