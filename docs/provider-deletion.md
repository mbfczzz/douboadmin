# 服务商结构删除

仅超级管理员可在服务商行点击“删除”。分公司删除包含其全部下级，按真实 parentId 逐层查找，无 500 条列表截断。预览展示服务商节点、后台账号及去重后的用户数量；需填写原因、输入服务商全名，并勾选“我确认同时删除上述用户账号”。提交前重新计算事务内快照，范围或版本变化返回 409，刷新预览并要求重新确认。

服务商记录标记为 deleted，后台列表隐藏，不可重新启用；关联后台账号归档并停用，现有会话立即拒绝；所有下级邀请码作废，会员及负责人归属解除，待审核登记拒绝并同步扫码记录。分公司手机号预绑定释放。平台 root 和含超级管理员账号的结构禁止删除。

按最新要求，当前归属的会员、负责人、待审核用户及关联后台账号的用户身份一并归档并停用；小程序、App 等端现有会话失效，活动用户列表隐藏这些账号。历史作品、充值订单、钱包、分佣账目及审计记录仅保留用于追溯，不物理清除。手机号占用释放，新注册账号不会继承历史权限或余额。已转到其他结构的用户不因历史登记被删除；如存在多重归属或结构外后台权限，拒绝删除并要求核对。

删除事务依次获取身份锁、按用户 ID 排序的钱包锁、服务商树锁，再重算确认快照；变化则整体回滚。补开账号也受锁与删除状态检查约束。

接口：`GET /api/admin/partners/{id}/delete-preview` 返回 name/providers/accounts/members/users/token；`DELETE /api/admin/partners/{id}` 提交 token/reason/confirm，confirm 必须为 `delete-users`。缺少确认的旧客户端被拒绝，避免旧提示框未告知用户删除范围就执行。服务端不信任客户端提交的影响数量。

不增加表结构。上线需部署新版后端及后台前端；未对实际业务结构执行删除。验证包括超过 500 个下级、旧预览冲突、权限拒绝、旧登录失效、邀请码失效及账目保留。

Go 全量测试、9 项后台浏览器回归、结构检查及 Web 构建通过。Web 首屏静态依赖 gzip JS 77.88 KiB / CSS 8.84 KiB，全部输出（包含异步块）JS 185.38 KiB / CSS 24.79 KiB；新增确认弹窗按需加载，性能预算通过且未更新基线。本功能不修改小程序源码，未测量微信最终上传包。

再次复查：删除事务内锁定并重新确认操作者仍为有效超管；权限在请求预检查后撤回也不能删除。已拒绝、已解绑的历史会员关系不计入影响数量、不重写。待审核记录及扫码记录同步拒绝，旧审核页面不能恢复删除节点。已删除用户无法继续登录；普通解绑后转入其他服务商的有效用户会获得新推广码，不返回旧作废码。

故障注入回归验证末尾审计写入失败会整体回滚。另在真实 MySQL 连接级临时表上验证 505 条记录完整读取、批量修改及回滚，业务表未变更；通过 `MYSQL_TEMP_TEST_DSN` 单独启用 `TestMySQLCascadeSnapshotAndRollback`，连接标记防止测试意外切换会话后触及同名持久表。

用户级联删除增量：确认框新增用户数量和独立勾选项，确认范围变化时同时清空名称和勾选状态。测试覆盖 506 个节点及 505 个用户、重复归属去重、跨端旧会话失效、手机号释放、外部用户不受影响、钱包历史保留和末尾失败全部回滚。Web 首屏 gzip 仍为 JS 77.88 KiB / CSS 8.84 KiB，全部输出（含异步块）JS 185.55 KiB / CSS 24.79 KiB。预算通过，总 JS 趋势提醒已触发；此次弹窗增加用户删除说明与确认项，未提高上限或重置基线。
