# 统一角色

用户开通仅允许超级管理员角色（`super_admin`）。平台运营、自定义管理员和所有服务商角色均无开通权限；前端隐藏按钮，服务端逐次按当前账号角色校验。角色改名或获得用户/服务商菜单权限不会获得开通权限。

角色沿用原有菜单授权，并增加小程序用户的角色展示用途。不再单独配置“身份”。

内置角色包括原有超级管理员、平台运营、通用服务商，以及分公司、S1 服务商、S2 推荐官、会员。前三种业务服务商角色使用原有服务商范围及菜单限制；会员是小程序角色，没有后台菜单，也不能分配给后台登录账号。

小程序通过 `/api/me/role` 读取角色名称及所属服务商。角色由原有的服务商绑定、会员归属与开通状态自动对应，不新增晋升或手工改变用户归属的流程。已有 `/api/me/identity` 保留同一响应形状作为旧客户端兼容入口；两者均从角色管理的定义读取名称。

修改角色名称和菜单不修改服务商父级、下级发展范围、审批人、定价、额度、分佣及积分逻辑。原有后台账号及自定义权限角色保留，不自动改写；新创建服务商登录默认使用对应分公司/S1/S2角色。通用服务商角色继续兼容已有账号。

四种新增角色为内置定义，无需数据迁移或手工建表；修改角色时仍写入现有 `admin_roles` 表。会员只能修改显示名称，不允许分配后台菜单；服务商角色只能使用已有服务商菜单和子树范围。用户未开通时不显示已生效角色。

后台树、登记记录、用户来源与审批确认通过只读 `/api/admin/roles/labels` 使用同一份业务角色名称。该接口只返回四种角色名称，不返回菜单权限和账号数量；用户查看员仅获得名称查询权限，不因此获得角色管理权限。角色改名不改业务类型代码。

服务商账号选择器仅显示当前层级对应的业务角色、通用兼容角色及自定义服务商权限角色；首次开通默认当前层级角色。已有通用或自定义角色保持选中，不自动替换，后端仍校验不匹配的业务角色。
