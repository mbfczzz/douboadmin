# FFmpeg 检测

「系统设置」提供 FFmpeg 检测面板，显示每个 API / Worker 节点的 FFmpeg 和 FFprobe 状态、版本、可执行文件路径与检测时间。「运行监控 → 运行节点」复用同一份检测结果。

- 检查固定的 `ffmpeg -version`、`ffprobe -version`，以实际服务进程的 PATH 和账号权限为准；不会执行浏览器传入的命令，不上传媒体，不安装或修改系统程序。
- 两项并行检查，每项最多运行 2 秒，命令输出最多保留 8 KiB，只展示识别后的版本与固定诊断信息，不回传原始标准错误。
- 通过 `GET /api/admin/system-tools` 手动重新检测当前 API；接口仅允许超级管理员访问，返回 `Cache-Control: no-store`。并发检测共享已经进行的检查，普通心跳检测缓存 30 秒。浏览器每 15 秒更新显示，离开页面即停止。
- Worker 每 15 秒随心跳上报自己的检测结果；普通检测结果缓存 30 秒，到期后随下一次心跳重新检查。当前 API 的成功不能代表其他节点可用。
- 未找到、执行异常、超时分别显示。60 秒未收到心跳的节点显示离线；超过 120 秒的检测结果显示过期；旧节点没有上报过结果时显示未检测，不会当作可用。

检测证明程序可被当前服务账号找到并成功运行版本命令，不替代具体视频格式、编解码器或完整业务链路的验证。检测失败不会自动阻止其他生成任务，也不修改现有参考视频处理逻辑。

部署时需要先运行现有数据库迁移，为 `instances` 表增加可空的 `media_tools` JSON 字段，再更新并重启全部 API / Worker，发布后台网页。标准原生部署流程已有迁移步骤。旧心跳记录保持兼容，升级后的节点会自动补报。

回归包含缺失程序、权限与执行失败、超时、版本解析、输出上限、并发缓存、主动刷新、请求取消不污染缓存、API 与 Worker 独立结果、桌面和窄屏状态展示。真实 MySQL 往返检查需配置专用测试库的 `MYSQL_TEST_DSN`，不应在业务数据库运行测试。
