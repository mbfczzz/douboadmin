# 小程序全页面用户体验检查

Method: dual-agent（A: mini_design_review · B: mini_ui_evidence），主代理合并核实。

## 范围和证据

检查当前 23 个注册页面及其源码分支，保留此前未提交的背景/边界修复。本轮只检查，没有修改业务代码。

- 两份独立评审分别检查设计/用户流程和代码/隔离运行证据。
- 23 页各取 320、390px 代表数据状态，生成 46 张 WXML 源样式投影，人工查看拼图与页面源码。修正投影器图片选择器和带表达式的自闭合标签解析后，代表状态无横向溢出。
- 投影使用隔离示例，图标、TDesign、原生控件、组件隔离、系统字体和动态高度不完全等价于微信。不能用这些截图证明全部状态、真机键盘、系统弹窗、相册或支付无问题。
- 34 项现有布局分组、视口、导航及主题检查通过。额外 harness 复现分页/筛选失配、重复密码重置、离页后响应写回和全部已读重复请求。
- 用户正在使用模拟器，本轮未操作它；没有真实短信、支付、生成、上传、分享创建或密码重置。
- 检测器输出 0 项，但不支持 WXML/WXSS，不能作为原生 UI 合格结论。

## 次要问题及设计建议

- 服务商主请求在页面卸载后仍可setData，隔离复现1次迟到写回；只对子列表做了版本保护，主请求需要同样处理。
- 消息“全部已读”缺少忙碌提示和防连点，隔离复现2次请求；接口幂等，属于反馈/效率问题，不夸大为重复扣费或数据丢失。
- 我的常用功能同时包含账户、作品和帮助，适合按用途分组；预留积分缺少解释入口，当前钱包里点击该文字实际上执行刷新。
- 注册姓名/手机号/验证码仅placeholder，填写后缺少持续标签；可补标签或可访问名称。
- 模板全库为空时仍建议“换个分类”，应依据实际是否有其他分类给出提示。
- 热门视频enabled初值false，加载期间可能先提示未开放；应区分读取中和确认关闭。
- 订单“支付单不能再次拉起支付”术语偏技术，可改为“此订单无法继续付款”；保留到账查询的真实业务约束。

## 评审结论

源码启发式评分仅用于排序，不是原生验收分：状态反馈2、现实语义2、用户控制3、一致性2、防错2、识别2、效率2、视觉简洁3、错误恢复2、帮助2，合计22/40。

已有共享主题、原生导航封装、会话隔离、分页接口、支付确认和资料未保存保护。主要欠缺是跨查询失败时状态一致性、少数操作的防连点，以及子页反馈完整度。已补卡片/底栏边界不作为本轮新缺陷；截图顶部作品被裁切可能是滚动位置，未证明导航遮挡。
