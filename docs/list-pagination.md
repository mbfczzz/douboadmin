# 列表分页

后台和小程序列表使用服务端分页。请求包含 `page`（从 1 开始）、`size`（默认 20，最大 100），返回 `{items,page,size,total}`。搜索和状态筛选先执行，再计算总数、选取当前页。默认按创建时间及 ID 倒序稳定排序；模板、模型按排序值及 ID 排序。

## 已接通的列表

- 充值订单、退款记录、个人积分流水、后台用户积分明细。
- 生成任务、作品，以及小程序任务、作品、素材库、聊天历史。
- 模板、模型、收藏、通知、用户反馈、监控错误日志及告警。
- 管理账号、角色、服务商树和小程序下级服务商。
- 原有用户、注册审批、支付流水、积分变动日志、分佣及提现等列表继续分页。

订单管理员列表支持 `q/status`；模板支持 `q/kind/category/status/sort`；模型支持 `q/kind`。积分变动日志每页 30 条，前端使用响应的 `size` 计算页数。小程序首页模板每次取 4 条，继续加载请求下一页。

## 特殊列表与统计

- `/admin/partners/tree?page=1` 返回根级；`parent` 指定展开的父级，返回其下级页；`q` 搜索所有可见服务商。权限范围完整查询，不受 UI 页码影响。
- `/provider/children?page=1` 仅返回当前服务商的直接下级。
- `/favorites/templates?page=1` 按有效收藏记录分页；`items` 是当前可见模板，`unavailable` 保留不可用收藏以供移除，`total` 包括两类。`/favorites/{模板ID}` 查询单条收藏状态。
- 通知额外返回全局 `unread`，全部已读通过有界游标批次更新本人通知。
- 用户生成历史提供分页；模型调用统计、积分实际消耗和作品总数从完整数据聚合，不使用列表长度充当统计。
- 操作日志、用户行为日志继续使用游标；模型/角色选择器和配置返回完整的选项元数据。

## 兼容与验证

新维护的列表客户端均显式传 `page`。旧的未传页码调用保留原响应形状，不能依赖它获取完整业务历史。配置、角色选项等完整内部查找使用独立完整查询。

回归包含超过 500 条记录的分页、搜索、权限及通知更新；超过 200 个任务的历史和聚合；前端翻页与筛选重置；小程序失败重试、重复点击及会话变化。测试使用隔离数据，不改真实订单或钱包。

无数据库结构变更。上线时应同时发布服务端与新客户端；微信最终上传包仍需在开发者工具内验证。
