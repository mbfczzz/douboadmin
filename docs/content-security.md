# 内容安全（UGC）

小程序用户写的文字和上传的文件交给微信内容安全接口（2.0 版）判定，不接第三方审核服务。

## 检测范围

| 内容 | 接口 | 时机 | 违规时 |
| --- | --- | --- | --- |
| 创作描述（含 Agent 对话、一键复刻、模板创作，`POST /api/jobs`） | `msgSecCheck`，场景 3（论坛） | 提交时，当场判定 | 拒绝提交：「内容可能含有违规信息，请修改后重试」 |
| 昵称与简介、注册姓名 | `msgSecCheck`，场景 1（资料） | 保存时 | 同上 |
| 创作项目名称、我的服装名称、分享标题 | `msgSecCheck`，场景 3 | 保存时 | 同上 |
| 上传的图片、音频（含头像） | `mediaCheckAsync` | 上传成功后在后台提交，结果由微信推送 | 素材标记为违规（`assets.secCheck = risky`），之后不能用于生成：「有素材未通过内容安全检测，请更换后重试」 |
| 上传的视频 | `mediaCheckAsync`（微信不收视频，取开头、中间和接近结尾三帧画面） | 同上 | 同上 |
| 公开分享的作品、被设为优秀的作品 | `mediaCheckAsync`，检测结果图片或视频画面（设为优秀时用作者的 openid） | 创建分享时、管理员设为优秀时 | 作品标记为违规（`work_meta.blocked`），分享链接和优秀作品都不再展示 |

- 文字超过 2500 字时分段检测，最多检测前 10000 字。
- 判定为「疑似（review）」时放行，在日志中标出，供人工复查；只有「违规（risky）」才拦截。
- 微信接口调用失败、超时，或用户没有微信身份（openid）时放行并记录，不影响正常创作。
- 微信要求 openid 对应的用户近两小时内访问过小程序。管理员设为优秀时作者若长时间未访问，检测会在日志中显示「调用失败」，此时以管理员预览为准。
- 只检测小程序用户（`user` 角色）提交的内容；管理员和服务商后台操作不检测。
- 给微信的文件地址是 OSS 签名地址，有效期 2 小时；图片缩到 1280 像素以内并转为 JPG，以满足微信的大小限制。日志里不保存可用的文件地址。

## 结果推送

`mediaCheckAsync` 的结果以 `wxa_media_check` 事件推送到小程序的「消息推送」地址，与虚拟支付共用：`https://<服务域名>/api/payments/virtual/notify`，Token 与 EncodingAESKey 使用后台虚拟支付配置里的值（安全模式，JSON 或 XML 都支持）。微信公众平台「开发管理 → 开发设置 → 消息推送」需要已启用并指向该地址；未配置时文件检测的结果收不到，文字检测不受影响。

待处理的文件检测记在 `content_checks`（id 为 `trace_id`）。重复推送只处理一次；推送早于检测记录保存时，最多等 1.5 秒再处理。生成的视频文件没有记录时长时，按任务时长取三帧。

## 后台怎么看出被微信拦截

- **日志管理 → 内容安全**：每次检测一行，「判定」列显示通过 / 疑似 / 已拦截 / 调用失败。被拦截的行标红，写明违规类型和处理结果，例如「微信判定违规（色情），已拦截「提交生成任务」」「……素材已禁止用于创作」「……作品已停止对外展示（分享、优秀作品）」。「结果」筛选选「已拦截或调用失败」只看这些。
- **作品管理**：被下架的作品状态为红色「违规下架」，下方注明微信判定的类型；状态筛选可选「违规下架」。这类作品不能设为优秀。
- **生成任务详情 → 输入素材**：未通过检测的素材标注「微信判定违规（类型）」。
- **小程序用户 → 行为日志 → 全部请求**：该用户的检测记录也在其中。

## 日志与提审材料

后台「平台管理 → 日志管理 → 内容安全」（以及「小程序用户 → 行为日志 → 全部请求」）列出每一次调用：请求参数（不含 access_token）、微信原始返回、判定摘要（通过 / 疑似 / 违规 · 类型）和关联的素材或作品。提审时可据此录屏展示接口返回值：

1. 在小程序创作页输入微信文档示例中的违规测试文本并提交，界面提示拦截；在日志「内容安全」中打开该条，展示 `msgSecCheck` 的返回（`suggest: risky`）。
2. 上传一张测试图片，展示日志中 `mediaCheckAsync` 返回的 `trace_id`，以及稍后收到的「文件内容安全检测结果」。

小程序端没有改动：拦截提示由服务端返回，沿用现有的错误提示。
